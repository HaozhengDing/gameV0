# 视觉与动效生产路线（矿井环境表现层）

> 主题：**矿井一层的"环境表现层"（风、尘、灯火呼吸、植被/支护摆动、玩家动作扰动）由谁、用什么方式生产**
> 日期：2026-11-21｜状态：**待试验**｜触发：用户提供抖音《进入 VibeCoding 大审美时代！审美复刻 EP02》（S1）
> 关联：`docs/01-decision-twist.md` D1 可读优先；`docs/tech/m1-feedback-juice.md`（M1-10 反馈层）；`docs/04-m1-plan.md` §1.1（M2 之前不做水墨后处理）

## 当前选择与理由

**取「引擎原生程序化」为主，只从参考作品复刻"运动参数"，不复刻美术风格；M1 只做一个最小场景，M2 再扩。**

理由三条：

1. S1 演示的项目（S2 原版 Pixel Play）是**纯装饰性交互艺术**——树会摇、风铃会响、天气能切，但**没有玩法因果**。本作的画面必须服务"看得懂物质在反应"（D1），直接照搬"好看的装饰层"会把"好看"和"读懂"拆开。
2. 但它的**可迁移部分恰好是本作缺的**：统一风场下"每棵树有相位差 + 振幅随机 + 松手回弹"的运动层次。这正是"空气在流动"的来源，与本作矿井（瓦斯、硫烟、水银蒸气）的语义同构。
3. 复刻工作流的成功率不稳（S4 论坛经验：复刻着色器"抽卡成功率五成算高了"，且"动图它其实看不太懂，最好再配关键帧加文字描述"）。把不确定性放在"参数"上可控，放在"整套视觉"上不可控。

---

## 症状

- 矿井一层现在能读（M1-10 反馈层的火光/火花/飘字已落地），但**除玩家与事件之外，画面是静的**：没有空气、没有光的变化、没有支护/竹木的微动。制作人近期试玩反馈集中在"机动性偏高"（`docs/log/2026-11-21-05-playtest-physics-fluid-settle-fixes.md`），尚未提画面——**这是待证项，不是已验证的需求**。
- M1 退出门（`docs/04-m1-plan.md` §2）第 4 条只要求"制作人自测觉得好玩、读得懂"，没有画面质量条款。

## 现版基线

| 层 | 现状 | 位置 |
|---|---|---|
| 世界绘制 | `SimWorldNode` 单张纹理逐 pixel 更新（CPU） | `game/gdextension/src/sim_node.cpp` |
| 事件表现 | M1-10 反馈层：符火、火星、爆散、飘字、白闪/红晕 | `game/scripts/feedback/` |
| 一次性脉冲 | 施法环、喷液线 | `game/scripts/overlay.gd` |
| 粒子 | 自绘数组（CPU 绘制，上限数百），非 `GPUParticles2D` | `fx_layer.gd` |
| 光照 | **无**（`CanvasModulate`/`Light2D` 都没用） | — |
| 数据 | 生物群系矿脉、三大 hazard、碑文 | `data/biomes/level-01-coalmine.json`、`biome_hazards.gd` |

## 约束

- **D1 可读优先**：任何环境层不得降低"8 条民俗反应 + 火/毒烟/熄灯"的辨识度；污染只遮蔽未知（D3）。
- **M1 范围**：不做水墨后处理、不做像素刚体碎裂（`docs/04-m1-plan.md` §1.1）。
- **性能**：内部分辨率 480×270、整数 4× 到 1080p；模拟预算 6 ms/tick 已用掉大半（burn-worst p95 0.82 ms，但典型场景要留给渲染）。渲染器是 **GL Compatibility**。
- **人力**：个人制作人 + AI；无美术。
- **买断制**，不引入运行时联网素材。

## 候选比较

### asset-replication

**做法**：按 S1 的"审美复刻"工作流，用提示词把 S2 那类现成像素动效（树的摆动/风场/天气切换）复刻成 Web 或 Godot 场景，再改造成矿井素材。

| 维度 | 内容 |
|---|---|
| 做法与适用场景 | 玩家在矿井里行走/施法时，环境给出统一的空气流动与物体微动；参考作品的"一屏三树 + 风向/风速/阵风"控件是现成的调参面板，适合快速出效果 |
| 证据与边界 | S1 是**演示级**证据：作者称"跑了很多轮提示词、几乎一比一还原核心交互"，画面确实呈现三棵树 + 天气/风向控件 + 计数器（Shaken 90,691 times）+ 延伸品风铃（Rung 5 times）。但**提示词正文与迭代过程未出现在可读范围**，也无帧率/工程数据。S2 证明原版是 **React/网页**作品、**代码需付费**，本作无法直接取其代码，只能取"效果"。S4 给出反例：复刻着色器成功率约五成 |
| 本作映射 | **缺失**的部分是"环境响应层"；**不可复用**的是美术风格（暖色樱花/秋叶与国风矿井冲突）与 Web 技术栈（React → Godot 需重写） |
| 代价与依赖 | 程序：生成 + 集成 1–2 人日，但每次重生成都要人工验看（S4 的"看不懂动图、需要关键帧+文字"）；美术 0；**风险**：版权（原版内容付费）、风格错配、复刻结果不可控 |
| 最小验证 | 同下节场景；额外记录"生成 → 可用"的轮次与返工率 |

### procedural-native

**做法**：在 Godot 内用 `CanvasItem` fragment shader 做深度/温度调色与光照呼吸，用 `GPUParticles2D` 做尘/火星/蒸气，风场用一份 2D 噪声 + 每物体相位偏移驱动，参数进 `data/`。

| 维度 | 内容 |
|---|---|
| 做法与适用场景 | 玩家走动/施法时：脚下扬尘、火把/灯火按呼吸曲线明暗、竹木支护随风轻摆、瓦斯区粒子向上飘；全部由 `sim_core` 的材质与事件驱动，**因果可见** |
| 证据与边界 | S3（Dome Keeper 技术拆解，自动翻译的二手转述）：① 深度用 fragment shader 在"地表暖色 ↔ 地下冷色"两套调色板间插值；② 动态光用 CanvasItem 软阴影贴图，"低分辨率光 + 限制同时生效的光源数"；③ 粒子用 `GPUParticles2D`，16×16 小纹理、寿命 <1 s、burst 避免尖峰、粒子调色板随深度渐变。**成熟度：技术可行 + 已发行实装的二手转述**，非受控实验 |
| 本作映射 | **部分已有**：粒子绘制、事件总线、反应取色。**缺失**：真正的 `GPUParticles2D`、`Light2D`/`CanvasModulate`、风场、深度调色。**待核实**：GL Compatibility 下 GPUParticles2D 与多光源的实测开销 |
| 代价与依赖 | 程序 2–3 人日（风场 + 粒子 + 调色 shader + 开关）；美术 0（程序化）；音频 0.5 人日（一条风声 loop）；依赖：无新数据契约，参数放 `data/magic_numbers.json` 或独立 `data/ambience.json` |
| 最小验证 | 见下节 |

### defer-to-m2

**做法（基线）**：M1 保持纯灰盒，环境层整体推到 M2 美术阶段。

| 维度 | 内容 |
|---|---|
| 做法与适用场景 | 不改画面，把人力全投 M1-06（敌人 + 旱魃 BOSS） |
| 证据与边界 | 符合 `docs/01-decision-twist.md` D4（M2 之前不做水墨后处理）；但 M1 退出门没有画面条款，所以"不做"同样合规 |
| 本作映射 | 现状本身 |
| 代价与依赖 | 0 成本；代价是 M1 门评审时画面仍是纯色块，"国风克苏鲁"只能靠文字与音效传达 |
| 最小验证 | 无需 |

## 条件化优先顺序

1. **先做 `defer-to-m2` 的一部分 + `procedural-native` 的最小切片**（推荐）：只做"矿井入口安全区 + 一段 Wang 矿道"的风、尘、灯火呼吸三件事，2–3 天；其余留 M2。
2. **若最小切片盲选失败**（制作人看不出差别，或帧时间超预算）：退回 `defer-to-m2`，把预算转给 M1-06。
3. **`asset-replication` 只在两种条件下启用**：① 需要一个"异质化的灵感冲击"（例如做纸扎/鬼市的视觉参考）；② 制作人明确接受"复刻的是运动参数，美术风格另行重画"。

## 最小验证（一周内可执行）

| 项 | 内容 |
|---|---|
| 场景 | 固定 seed `20261121` 的矿井入口安全区 + 向北 3 屏矿道 |
| 基线 | 当前 build（只有 M1-10 反馈层） |
| 只改的变量 | 新增 `environment layer`：① 全局风场（1 张 2D 噪声，16×16 采样，方向 30°–60°）；② 尘（每屏 ≤ 40 个 `GPUParticles2D` 粒子，寿命 0.8 s）；③ 灯火呼吸（`CanvasModulate` 亮度 ±4%，周期 3.2 s，随机相位） |
| 观察项 | ① 1080p GL Compatibility 帧时间增量（目标 ≤ 0.5 ms）；② 10 s 录屏 A/B 盲选（制作人 3 次，≥2 次偏好开启）；③ 8 条反应的辨识度不下降（用 `docs/tech/m1-feedback-juice.md` §5 的核对表逐条打勾） |
| 通过标准 | 性能达标 + 盲选 ≥2/3 + 反应辨识无回退 |
| 回退条件 | 一条开关 `ambience_enabled = false` 关掉整层，不留痕 |
| 记录 | 帧时间、盲选结果、返工轮次写回本卡"已试验"段 |

## 待证项

- GL Compatibility 下 `GPUParticles2D` + 多光源的实测开销（本卡最大未知）。
- "环境层能提升可读性"目前是**推断**，不是实测；也可能只是"更好看"而与玩法无关。
- S1 的提示词正文未读到；"几乎一比一"是作者自述，未经独立复现。
- S3 是自动翻译的二手技术拆解，Dome Keeper 的原始演讲/博客未回查。
