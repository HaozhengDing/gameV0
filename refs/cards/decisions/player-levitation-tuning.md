# 人物机动性与浮空条收敛（含下落低速回充）

> 主题：**如何把偏高的玩家机动性与过长的连续浮空收敛到有压迫感的区间，同时检验「下落时略低速回复漂浮条」是否可行且不引入无限滞空漏洞**
> 日期：2026-11-21｜状态：**待试验**｜触发：制作人连续两次实机试玩反馈（2026-11-21-05 #3 + M1-α 反馈 #3：「人物机动性还是高，漂浮时间稍长，我觉得下落的时候可以略低一些速度回复漂浮条」）
> 关联：`game/scripts/player.gd`、`docs/tech/m1-jump-feel.md`（P0 已落地，§4.5 曾暂缓增机动项）

## 当前选择与理由

**优先试验 `shorter-hover-plus-fall-regen`（把连续浮空从 1.92 s 压到 ~1.15 s、下调上升极速与平跑速度，并参照 Noita 双速率机制加入「下落延迟 + 极低速空中回充」），同时留开关与 `ground-only-strict-nerf` 做 5 分钟同矿井 A/B 对比。**

理由三条：

1. **制作人的直觉恰好与 Noita 原版底层一致**：Noita 的 `CharacterDataComponent` 正是「落地快充（`fly_recharge_spd_ground`）+ 空中慢充（`fly_recharge_spd`）+ 停推等待帧（`flying_in_air_wait_frames`）」三参数组合，而非彻底禁止空中回充。
2. **现版机动过强有明确量化根因**：① 连续浮空 `100 / 52 = 1.92 s`，一口气能飞 ~165 格（超过 70% 的整间矿室高度）；② 浮空上升极速 `HOVER_MAX_UP = -96` 比水平跑速 `MOVE_SPEED = 68` 还快 41%，且推力分支未扣重力，导致玩家在矿井和 BOSS 房里像装了喷气战斗机。
3. **只要满足严格的数学防线，下落慢充绝不会变成无限滞空**：限定「必须已进入明显下落（`vy > 24`）+ 停推满 `0.28 s` 延迟 + 回充速率低于消耗速率的 1/5（`16/s` vs `86/s`）」，坠落 1 秒只够换 0.13 s 落地前微刹，既给竖井坠落留安全感，又在数学上杜绝点按永动机。

---

## 症状

- 即便 M1-06 小怪与旱魃已会追击与射击，玩家仍觉得「人物机动性还是高，漂浮时间稍长」，能轻松长时间滞空绕开地面威胁与火势。
- 同时制作人希望探索：**缩短单次漂浮上限后，下落过程能否以较低速度缓慢回复一点漂浮条**（让下落与节奏衔接更顺，而非非黑即白的纯落地重置）。

## 现版基线

| 常量（`game/scripts/player.gd`） | 现值 | 实际体验量化 |
|---|---|---|
| `MOVE_SPEED` | `68.0` cells/s | 3.5 s 横穿半屏；高于所有矿井小怪与旱魃（`42`） |
| `HOVER_MAX_UP` | `-96.0` cells/s | 向上飞比平跑快 41%，空中脱战极轻松 |
| `HOVER_ACCEL` / `HOVER_BRAKE_ACCEL` | `480` / `780` cells/s² | 推力分支未减重力，滞空拉起极猛 |
| `LEVITATE_MAX` / `LEVITATE_DRAIN` | `100.0` / `52.0` /s | **连续浮空 1.92 s**，单气直飞 ~165 格（整间房高 224 格） |
| `LEVITATE_REGEN` / `DELAY` | `165.0` /s / `0.08` s | **仅 `on_ground` 回充**，0.60 s 满槽；空中 0 回充 |
| `m1-jump-feel` P0 | `COYOTE=0.10`, `BUFFER=0.10`, `CUT=0.10/0.35` | 已落地，防吞键、不增机动上限 |

## 约束

- **地形可达硬红线**：矿井 Wang 竖井与水银池深约 60–80 cells，单管满浮空**必须仍能从 75–85 格深的池底/竖井一口气飞回平巷**（绝不能因为砍浮空导致玩家掉进水银池或矿井底软锁！）。
- **防无限滞空（Anti-Infinite-Flight）**：任意频率点按 W/Space 均不可在空中维持净高度 ≥ 0，须写入 `--t4b-smoke` 自动化防回归断言。
- **不破坏刚落地的跳跃 P0**：起跳冲量 `JUMP_IMPULSE=-82`、重力 `GRAVITY=260` 与短跳切断参数不动，保持紧凑跟手。

## 候选比较

### shorter-hover-plus-fall-regen

**收紧平跑与单次浮空续航（1.92 s → ~1.16 s，单管仍可攀升 ~88 格不软锁），并引入 Noita 式「停推延迟 + 下落慢充」。**

| 维度 | 内容 |
|---|---|
| 做法与适用场景 | 调整 `player.gd` 5 项参数（均为假设试验初值）：<br>① `LEVITATE_DRAIN`: `52 → 86` /s（连续浮空 **1.16 s**，单气爬升 ~88 格，刚好覆盖 80 格水银池与竹木高台，无法一口气飞穿整间 224 格矿室）；<br>② `HOVER_MAX_UP`: `-96 → -76` cells/s、`HOVER_ACCEL`: `480 → 390` cells/s²（压掉"喷气战斗机"感）；<br>③ `MOVE_SPEED`: `68 → 60` cells/s（小幅收敛，与改版后的旱魃/小怪压迫对齐）；<br>④ 新增 **下落慢充**：仅当 `not on_ground` 且 `not thrust` 且 **`velocity.y > 24.0`**（明确处于下落态）且 **`_air_regen_delay <= 0`**（停推后须等 `0.28 s` ≈ 17 帧自由落体）时，`levitate += 16.0 * dt`（落地仍按 `145.0/s` 快充，约 `0.69 s` 满）；<br>⑤ **防无限飞数学核验**：`air_regen(16) / drain(86) = 0.186`（不足 1/5）且带 `0.28 s` 延迟——连续点按飞 0.3 s + 落 0.5 s，净耗 `25.8 - 3.5 = +22.3`，4 个周期内必然空槽落地；但从矿井长竖井坠落 1.2 s 可回 `(1.2 - 0.28) × 16 = 14.7` 能量（约 0.17 s 缓冲刹车），手感和容错明显好于纯干摔 |
| 证据与边界 | **S1 / S2**（Noita `player.xml` / `CharacterDataComponent` 参数说明，多处社区与存档编辑器文档交叉印证，已发行实装）：Noita 原生拆出 `fly_time_max`、`flying_in_air_wait_frames`（官方为防 "tap-tap-tap" 无限滞空专门加入的停推等待帧）、`fly_recharge_spd`（空中慢充，默认 `0.4`）与 `fly_recharge_spd_ground`（落地快充，默认 `6`，为空气的 **15 倍**）；**S3**（喷气背包平台游戏设计防无限飞分析，经验线索）：总结了空中回充速率 ≥ 消耗速率导致悬停漏洞的风险与延迟/速率硬上限的解法。具体到本作 `86 / 16 / 0.28 s` 这组数属于**本作物理换算假设**，需实机微调 |
| 本作映射 | **已有**：`player.gd` 已有 `LEVITATE_*` 与 `_regen_delay_timer` 结构；**缺失**：独立的 `AIR_REGEN_DELAY`、`LEVITATE_AIR_REGEN` 与 `velocity.y > 24.0` 下落门槛判断；同步可在 `--t4b-smoke` 加一条「180 帧高频点按必净下落且耗空」反作弊断言 |
| 代价与依赖 | 程序极低（约 15 行改在 `player.gd`，顺手可同步进 `data/magic_numbers.json`）；美术/音频 0（HUD 黄条自然呈现慢回涨）；零新契约；风险是若 `LEVITATE_AIR_REGEN` 调得过高仍可能削弱紧迫感，因此必须从偏保守的 `14–16 /s` 起步 |
| 最小验证 | 固定 seed `20261121` 跑三处场景：① 掉进 `room-01-silver-pit` 池底确认单管气仍能顺利飞出；② 在 `room-boss-coalmine` 与旱魃实战 3 分钟检验走位压迫感；③ 在高竖井试着高频点按 W 确认无法无限滞空，且长坠落末尾可轻刹。自动回归：`--t4b-smoke` 新增单气爬高 ≥ 80 格 + 点按防无限飞断言 |

### ground-only-strict-nerf

**对照组：采用同一组收紧后的浮空/跑速参数（1.16 s 续航、`-76` 极速、`60` 移速），但维持「仅落地回充」，空中回充 = 0。**

| 维度 | 内容 |
|---|---|
| 做法与适用场景 | 不加下落慢充，把所有精力放在收紧连续浮空与上升速度，强迫玩家在平台间落地换气 |
| 证据与边界 | **S3**（地面回充范式，经验线索）：关卡纵深最可控、零空中循环漏洞；反例是像 Noita 这类存在深竖井与可挖地形的沙盒，一旦高空耗干气，长坠落过程完全无法微调落点（这也是 Noita 保留 `fly_recharge_spd` 的原因） |
| 本作映射 | 改 `player.gd` 4 个常量即可 |
| 代价与依赖 | 程序极低；唯一风险是长竖井坠落容易因为气空摔进岩浆/硫火而觉得发僵 |
| 最小验证 | 与 `shorter-hover-plus-fall-regen` 共用一条开关 `LEVITATE_AIR_REGEN = 16.0 vs 0.0` 做 5 分钟同矿井 A/B 试玩盲选 |

### keep-current

**基线：保持 `1.92 s` 连续浮空、`-96` 上升极速与 `68` 跑速。**

| 维度 | 内容 |
|---|---|
| 做法与适用场景 | 不改 `player.gd` |
| 证据与边界 | 制作人已在 2026-11-21-05 与 M1-α 两次明确反馈偏高，仅作对照基线 |
| 本作映射 | 现状本身 |
| 代价与依赖 | 0 改动；代价是削弱矿井纵深感与 BOSS 弹幕压迫感 |
| 最小验证 | 作为 A/B 参照基线 |

## 条件化优先顺序

1. **先做 `shorter-hover-plus-fall-regen`**，并保留 `LEVITATE_AIR_REGEN` 为可一键置 `0` 的常量，方便和 `ground-only-strict-nerf` 立即对照。
2. 顺带确认：原先 `docs/tech/m1-jump-feel.md` §4.5 推迟的「顶点悬停 / 速降补齐」在机动性刚下调的阶段**继续保持推迟**，避免刚压下去的机动性又被拉回去。
3. 实机敲定参数后，将 `player` 移动/浮空关键数值正式落入 `data/magic_numbers.json` 并记 `v1_deviations`。

## 待证项

- 单气爬高 ~88 格在 5 个不同 seed 的 Wang 竖井中是否 100% 不出现「掉下去飞不上来」的局部地形（需用 5-seed 实跑或脚本测最大垂直落差）。
- `MOVE_SPEED` 从 `68` 降到 `60` 后，与新旱魃 BOSS 的滑步突进/扇形火弹配合是否过紧或刚好。
