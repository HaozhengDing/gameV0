## 结论

- 新增 `sim_core/`：C++17 + CMake、无引擎依赖的单线程模拟库；公开头 `include/sim/c_sim.h` 即契约 **C-SIM v1**，实现了 chunk 64×64 + 脏矩形 + 休眠调度、powder/liquid/gas/static、沙/水/油/火/水银 5 种物质 + 挖掘，运行时读 `data/materials.json`（读不到回退 builtin）。
- 基准程序固定 seed 20261115 跑 10,000 tick，两场景（worst 480×270 全屏混合；typical 1440×810 矿井灰盒、活跃视口 480×270）。开发机 p95：worst 2.245 ms、typical 0.145 ms，均低于 D4 线（6 / 2 ms）。**但这是开发机（手机）数据，按 D4 不算实验 A 通过**；报告已标「开发机数据，非 go/no-go 依据」。
- 5/5 ctest 通过；确定性：本人用独立 build 目录复跑，30 张过程帧与原构建逐字节一致（md5 全同）。
- 契约文件冻结点：`sim_core/include/sim/c_sim.h`（改破坏性接口须 +1 版本号）。

## 决定与理由

| 决定 | 为什么 | 代价 |
|---|---|---|
| C-SIM 用 C ABI 头文件冻结 | T4 的 GDExtension（C++/godot-cpp）可直接 include；语言边界稳定，内部实现可换 | 需要在头文件里写清所有单位/所有权/线程语义 |
| chunk 64×64 + 脏矩形 + 休眠 | 渲染只需上传脏区；典型场景只处理活跃 chunk，是 typical 场景余量的来源 | 休眠语义有坑：上 tick 无写入的 chunk 不处理，活动区边界按墙处理（报告 §6.7 已写） |
| 沙 / 油 / 火定义在 sim 内，不改 `data/materials.json` | T2 原文即「沙和油作为实验物质另加」；data 的 12 物质与 P0 对齐，不能为原型扩表 | 物质来源分裂为「data 覆盖 + sim 内建」，报告 §9 写清来源；正式数据化留到反应表补齐时 |
| 基准含「wake 强制唤醒」跑法 | 休眠会让 typical 数字偏乐观；强制唤醒给出上界，目标机复测要求两个数都报 | 多一次 10,000 tick 运行（开发机 5 s 级） |
| 基准场景维持（注入/置换/复点火）放在计时区外 | 只为让 10k tick 内场景不完全沉降；计时只包 `sim_world_step` | 压力 harness 是合成的，不代表真实玩法事件频率（报告 §6.5） |
| 只提交 4 张代表帧，build 产物 gitignore | 30 张 PNG 约 3 MB，进 git 历史不值得；报告记录全部帧的生成方式 | 想看完整过程帧需本地跑基准（命令在报告 §8） |

## 基准结果（开发机，真实跑出，Lead 已独立复跑）

| 场景/跑法 | p50 | p95 | p99 | D4 线 |
|---|---|---|---|---|
| worst-wake（保守上界） | 2.068 | **2.245** | 2.407 | ≤ 6 ms ✅ |
| worst-sleep（默认休眠） | 1.098 | 1.459 | 2.338 | ≤ 6 ms ✅ |
| typical-sleep（默认休眠） | 0.107 | **0.145** | 0.228 | ≤ 2 ms ✅ |
| typical-wake（敏感性上界） | 0.468 | 0.478 | 0.502 | ≤ 2 ms ✅ |

Lead 独立验证：干净 build（0 warning）+ ctest 5/5 + 同 seed 复跑 p95 2.248 / 0.144 ms；跨构建 30 张过程帧 md5 全同。**数字仅开发机（Cortex-X3 手机）**，D4 明确要目标机（i5-8400 级）复测，见报告 §7。
