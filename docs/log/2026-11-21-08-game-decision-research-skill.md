- 触发：制作人希望 DeepSeek Harness 能复用抖音项目的卡片流程，为 gameV0 各个设计抉择跨平台寻找成熟做法。

## 结论

新增项目级技能 `game-decision-research`。技能从现版和试玩症状出发，检索能影响取舍的外部案例，为每个候选做法写一张可复查的卡，最后给制作人一个可回退的最小试验。首个样例用 M1-10 已有反馈层作为基线，比较命中音色、镜头位移和全局顿帧的适用条件。

## 决定与理由

| 是什么 | 为什么 | 代价 |
|---|---|---|
| 技能随项目进 `.dsh/skills/` | Harness 能按项目根目录发现，且卡片模板直接连接 gameV0 的约束、代码和历史 | 技能依赖项目目录结构。网页和媒体提取取决于当前会话开放的工具 |
| 以单个可验证的做法写卡，以决策主题组织 Markdown | 沿用抖音项目可回查的证据与派生卡思路。同一做法可以累积多来源，也可从同一个视频提取不同做法 | 每次要核对相同做法并更新来源。纯 Markdown 便于审阅，后续批量汇总需要另加结构化处理 |
| 用现版 A/B 验收本作适配 | 现版已有反馈层，也有环境 DoT 顿帧带来移动卡顿的试玩记录。外部案例帮助选择试验方向，本作体感由本作验证 | 需要窗口实机复现和制作人判断。自动 smoke 负责事件、时间缩放和复位等可测行为 |

本技能的硬输入是具体抉择和 gameV0 的现版资料。网络来源是可增补的软依赖。输出为决策主题、方案卡和日志。采纳候选仍是制作人的决策依赖。

## 验证与待决定

- 用本机 Harness 的项目级注册表验证了发现、加载、调用权限和资源路径，并验证了匿名 HTTP 抓取。实际会话的原生搜索与视频提取取决于该会话配置。
- 用「悬崖边短按漏跳，同时觉得人物太灵活」做离线演练。现有报告和代码足以拆出输入采样、离台宽限和落地缓冲三个可独立验证的候选，独立外部证据继续标为待核实。
- 打击感样例的状态为待试验。

## 下一步

遇到具体手感或设计问题时，在 gameV0 的 Harness 会话中输入 `/game-decision-research <问题>`。打击感样例可直接复用现有基线和来源。
