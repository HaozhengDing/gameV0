## 决定与理由

| 决定 | 为什么 | 代价 |
|---|---|---|
| C-SIM 升 v2（append-only 9 种 data 物质） | data/rooms 的房间需要 coal/saltpeter/sulfur/bamboo 等；把 data 的 12 物质全部落进模拟，灰盒才不是「替身映射」；只在末尾追加，已有 id/语义/基准不变 | C-SIM 版本 +1（按契约规则记 log）；材质数组 7→16，5 物质基准数字不变（bench 未重跑，语义验证由 ctest 确定性覆盖） |
| 命中简化为即时命中（不做投射物实体） | T4b 验收是「可玩 + 组合生效」，投射物飞行/穿透/命中判定属 M1-02/04；VM 的 C-ACT 树照常生成与执行（payload/trigger 立即结算） | 视觉上没有飞行物；「触发」体验打折；T4b 不判 go/no-go |
| 火格按墙处理 + 7 盏灰盒掉血 | 火是气体、本身不阻挡，若不按墙处理，「必须灭火」不成立；7 盏是 M1 七星灯的占位 | 玩家可能觉得火障偏硬；`player.gd FIRE_BLOCKS_MOVEMENT=false` 可退回软版 |
| 喷水灭火半径 12（原规格 3） | 16 格高火墙下半径 3 只能开 7 格缺口，10 格高角色过不去；12 才能整面熄灭（3 格宽火墙） | 灰盒调参，非设计数值；T5 试玩后调 |
| 房间按 `tile_size=16` 展开 | rooms JSON 的 grid 是 tile 网格（24×14，tile_size=16）；1:1 放置时房间只占屏幕 5%，不可玩 | 关卡常量与 BFS 重做一轮；房间内部障碍（竹木）需绕行 |
| 角色 5×10 cells（20×40 px @4x） | D4：1 cell = 1 世界像素、480×270 内部分辨率、4 倍放大；角色应约 1/4 屏高 | 走廊/门洞按 16 cells 设计 |

## 踩到的坑

1. **C++→GDScript 字符串不是 UTF-8**：`String(std::string.c_str())` 把 UTF-8 当 Latin-1，HUD 卡名乱码（飞剑·煞 → 飊áĉ）；改 `String::utf8`。
2. **房间 grid 是 tile 网格**：`tile_size=16` 不解释成世界尺寸，房间会变成 96×56 屏幕像素的邮票。
3. **MSVC 源码编码**：`/utf-8`（T4a 已记）。
4. **能力查询缺口**：T4a 只暴露 7 种材质与整图渲染；T4b 需要 `render_region/is_solid/get_material_*`，已补进 C-SIM v2 包装层（未改 C-SIM 语义）。
5. HUD 中文需要系统字体 fallback（Godot 默认字体不含 CJK）。

## 新增或修改的 deviations

- **C-SIM 版本 1 → 2**（契约规则：破坏性修改要 +1；本次为 append-only，已有 id/语义不变）。
- T4b 灰盒占位值（非设计数值）：火伤 7 盏、喷水灭火半径 12、角色 5×10 cells、房间 tile 展开 16、世界 960×540。复议：T5 试玩时按手感调；T4b 不判 go/no-go。
