## 决定与理由

| 决定 | 为什么 | 代价 |
|---|---|---|
| VM 做成纯函数 + 卡表只读注入 | 不依赖世界/引擎，可单测、可回放；卡表接口后续换成正式数据不改 VM | 调用方要自己备卡表；M1 接正式符表时要写一层数据加载 |
| 比较逻辑放 C++ harness（Python 只做 YAML→JSON） | 「用例是否通过」由被测语言自己判定，Python 只做数据转换，避免两侧各写一套期望逻辑 | harness 代码量较大（~1000 行）；但只在测试路径，不进库 |
| 30 条契约用例与新增边界回归分开 | 30 条是 T1 冻结契约（D4 的通过标准），不能随意增删；复审发现的覆盖外语义用独立 ctest 守护 | 边界测试的期望值来自 spec 补写后的口径，用户审定 spec 后若改语义需同步改（已在 README 声明） |
| 替换句带触发取 Option B（触发子句作废、游标停子句首） | 不改 C-ACT（phantom_cast 无 trigger 字段），确定性强、成本不变；Option A 需改契约 + T4b 世界层支持幻符延迟触发 | 替换会吞掉该句触发（`敕·触 + 幻符` 组合失效）；已列待拍板 #6 |
| 复审问题全部修掉，不靠改用例绕过 | 用例是契约；实现与 spec 不符应修实现或补 spec 空白，不能放宽期望 | 多花一轮复审时间（约 20 分钟） |
