## 结论

1. **产出 M1 正式开发计划草案**（`docs/04-m1-plan.md`，待用户审定）：锁定矿井 1 层完整 MVP 范围（守住 D1–D5 不扩 scope）、9 周时间盒（8 周开发 + 1 周冷却）、12 项任务的输入/输出/四类依赖与关键路径（`M1-01 → M1-12 → M1-06 → M1-08 → M1-09 → M1-11`）、8 条反应落地清单，以及 5 条待拍板项（D-M1-1~D-M1-5，全附 AI 推荐默认值）。
2. **显式登记 M0 Conditional 风险与中途止损点**：跳过目标机复测与外部 5 人盲测的代价在 `04-m1-plan.md` §1.2 显式留痕，并在 **M1-α（W4–W6 节点：反应表+战斗+1 层可打怪/旱魃）** 强制插入目标机补测与 2–3 人小规模盲测，避免隐患拖到 M1 结尾。
3. **产出 M1-01 契约草案 v0.1**（`docs/tech/m1-01-contracts-evt-text.md`）：定义 **C-EVT v0.1**（纯数据事件信封 + 4 大类 22 条事件 + D1 可读性双通道映射 + C-SIM v3 底层 `sim_event` append-only 扩展点）与 **C-TEXT v0.1**（`$domain_id` 兼容现有 `$mat_*`、融合 `refs/naming.md` §5 极简命名原则，并用 `corruptible: bool` 让 `validate_data.py` 机器强制守护 D3「只腐坏未知、不腐坏已知」红线）。
4. 同步更新 `docs/03-roadmap.md` 的阶段门状态与 C-EVT/C-TEXT 契约指针；未改动任何代码、数值、数据或 D1–D5 路线。

## 决定与理由

| 决定 | 为什么 | 代价 |
|---|---|---|
| M1-12（C-SIM v3 反应表 + 热/火）与 M1-02（投射物战斗）在 W2–W3 并行作为最先开工项 | 符合 03 §6 与 `sim-fire-heat-design.md`：战斗需要 `burning`/`wet` 与反应伤害来源，关卡需要黑火药/硫烟/蒸汽，早做早测性能 | 两条线同时动 C++ 与 GDScript，需严格以冻结的 M1-01（C-EVT/C-TEXT）为边界 |
| 在 C-TEXT 引入强制字段 `corruptible: bool` | 把 D3 红线（「只腐坏未知信息，已学符名/法器/反应永不乱码」）从口头约定变成 CI 可自动校验的硬约束 | 新增文本条目须多写一个布尔值与（当 true 时）手写 `corrupted` 变体 |
| M1-04 矿井拓扑建议先做网格拼室（D-M1-2），Wang Tile 留 M2 | M1 只验证「一层好不好玩」；网格拼室稳定、可控、零卡死地形，省出 1.5–2 周给核心反应与战斗 | 地形边缘不如 Wang Tile 自然（待 M2 垂直切片补） |
| 入魔最小集建议先精简 4 条（D-M1-1），暂缓「每 30s 失控 1s」与「魇烬」 | 失控抢夺操作权易引起挫败感，魇烬依赖 v2 阴火；4 条核心即可完整跑通「归零入魔→杀心魔回神智→出魔留魔痕」的风险收益闭环 | 少了失控的惊悚压迫感与魇烬掉落（可按用户拍板选回 S-0004 全部 5 条） |
