# 2026-11-21-19 多角色选择系统设想评估（初始方士 / 纯近战 / 纯触手邪神子嗣）

- 日期：2026-11-21
- 作者：Antigravity
- 类型：建议 + 评审
- 篇幅：摘要
- 触发：制作人提出后续新增多角色选择系统设想（当前方士作为初始角色，后续扩充纯近战角色与纯触手移动的邪神子嗣等）

## 结论

**完全可行、架构天然兼容，建议排入 M3/M4（EA 扩张期）正式落地，M1/M2 不破范围。**

- **为什么架构天然好接**：当前 `player.gd`（移动）、`wand_manager.gd` + `TalismanVM`（攻击/资源）、`vitals.gd`（血灯双轴）与 `CombatManager`（伤害/打击感）已天然分层；敌方 AI 只依赖 `player.cell_pos()` 与 `velocity`，不绑定浮空逻辑。后续只需新增 `data/characters.json` 与可插拔 `Locomotion`（浮空 vs 4–6 触手射线抓墙）+ `CombatKit`（法器符箓 vs 近战弧斩），**零改动 `sim_core` C++**。
- **为什么放 M3/M4**：延续 2026-11-16 D3 拍板（M1/M2 不做角色机制分化，防止平衡与内容乘法），先守住 M1 一层闭环与 M2 Demo 门。
- **必须守住的 D1 红线（别做成脱离沙盒的常规动作角色）**：
  - **纯近战角色**：刀身蘸水/黑狗血/朱砂/油附魔、重斩掀液扬粉、把怪劈进水银池或瓦斯囊，把打击感直接焊在元素反应上；
  - **触手邪神子嗣**：触手抓附 `SIM_STATE_STATIC` 岩壁全向爬摆（参考 Noita Lukki / *Carrion*），天然低神智亲和，但受 `r-quicksilver-ward` 约束不能抓水银，与民俗材质深度咬合。
