## 决定与理由（草案语义，待审）

| 决定 | 为什么 | 代价 |
|---|---|---|
| 两阶段：施法时解析（静态展开触发子句）→ 执行 | 递归深度/动作数/投射物数都可预算、可测试（C46）；避免命中时递归导致成本散落多个 tick | 触发子句「预付费」：施法时就扣灵力/神智，不符合延迟触发的直觉（待拍板 #2） |
| 灵力按句原子：句首判费，不足整句不念、本轮结束 | 一发能不能放出来是二元、可预判（法器可读性） | 差 1 点灵力就整发哑火，手感硬（待拍板 #3） |
| 游标逐符推进、不回绕；乱序只在回符时洗牌一次 | 单轮读符量可预测；乱序只影响「哪张符进哪句」，不改句法 | 长触发链消耗牌堆快，单轮爆发上限低 |
| 触发上限建议 深度 3 / 动作 64（按 count 展开计）/ 投射物 32，预算按一次 cast 共享 | C46 要求上限；64 ≈ 5 张分身 × 3 符脚；32 发在 480×270 已满屏 | 极端组合会被「钳制 count」截断，需要 UI 明确提示（待拍板 #5） |
| 动作列表由 VM 产出、世界层执行（C-ACT）；物质 id 只能取 data 的 12 个 | 这是 VM 与 T4 之间的唯一接口，也是「反应表是动作来源」的落点 | VM 动作与 data 8 种 result.type 的映射需长期维护 |
| S-0004 的禁符/幻符规则逐条落成时序（反噬优先、禁符与幻符不同次、含禁符不掷 15% 骰、幻影符 ≥33 清除） | 已定决策不能改；VM 必须与卡面完全一致 | 反噬施法扣费 clamp 到 0 等边界需用户确认（待拍板 #4 附带项） |

## 新增或修改的 deviations

未改设计原文/数据数值；以下**冲突/缺口写进 spec §7.3/§7.4，待用户定**：

- 「每念几符」的单位：草案取「句」（`sentences_per_cast`），与设计文档原词有歧义（批注 C06 已指出）。
- `归` 的灵力成本：草案取 cost 0 / 返还 8，才能满足 F-0004 的 `spirit_cost 10, refund 8, net 2`（土遁 10 + 归 0）；与 S-0002「符脚 +8~+30」冲突。**未改 data/ 与卡片，等用户拍板。**
- 数据缺口（用例已绕开并声明）：化·金、墨弹（ink）、蒸汽材质、幻符池、洗牌 RNG 算法、五雷「导电传导」；均属反应表/数据补齐后再加用例。

## 未解决 / 待决定（需用户拍板，5 条）

1. 「每念几符」单位取句还是符数（Noita 式）。
2. 触发子句付费时点：施法时静态展开预付费，还是命中时结算。
3. 灵力不足：整句不念（现状）还是念到哪算哪。
4. `归` 的 cost 0 + 返还 8（影响 F-0004 探索自循环）与反噬施法不足时扣 `min(spirit, 成本)`。
5. 三个上限数值 3 / 64 / 32（建议值，试玩后调）。
