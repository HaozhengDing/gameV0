## 0. 一句话定位与命名

**「天地不仁，以万物为刍狗。」**——这是中文典籍里最克苏鲁的一句话，建议直接作为游戏的主题句。宇宙的冷漠（cosmic indifference）在中国语境里不需要借洛夫克拉夫特，老子早就写好了。

> **📝 批注 C01｜P1｜主题解释｜原文 L7**  
> 作为艺术命题非常有力，但“天地不仁”不宜直接等同于洛夫克拉夫特式的恶意或宇宙冷漠。建议区分“原典解释”和“本作设定”：本作可以将其重新诠释为世界不以人的善恶为运行尺度。


- **工作标题**：《刍狗》（备选：《渎》《归墟》《太岁》《烛阴》）
- **一句话**：在一个以《山海经》《道藏》《天工开物》为底色的像素物理世界里，你是一名用符箓"编程"的方士，一层层潜入归墟，直面"天地不仁"的真相。
- **类型**：像素级物理沙盒 × 法术编程 × 高难度 Roguelike × 民俗克苏鲁

> **📝 批注 C02｜保留｜一句话卖点｜原文 L11**  
> “符箓编程 × 可模拟物质”比“民俗克苏鲁”更能概括可玩性。建议市场宣传按“可操作体验→视觉识别→世界观”排序，而非反过来。


**为什么这个方向可行**：Noita 的四根支柱——像素级物理模拟、组合式法杖构筑、无元进度的严格永久死亡、至今仍在被社区挖掘的隐藏秘密——几乎没人敢完整复制，大多数"类 Noita"只抓了其中一两条 [cite:313b1036-5]。而"国风克苏鲁"的需求是被验证过的：《明末：渊虚之羽》发售前愿望单破百万、首日峰值 11.4 万在线，但因优化等问题评价两极化 [cite:2246f3cb-2]。这说明题材有大量存量需求，同时也警告你：**题材只能把人骗进来，留住人靠系统深度和完成度**。

> **📝 批注 C03｜P1｜市场证据｜原文 L13**  
> 原文引用的 [cite:...] 为未展开的来源标记；在本批注中不视为已核验的证据。Noita“无元进度”的绝对表述也不准确（存在跨局解锁）。《明末》的热度不能直接推导出该玩法的付费需求；应以竞品样本、愿望单转化和真实试玩检验。

## 一、游戏定位与核心玩法

### 1.1 对标 Noita 的四根支柱，以及我们每根支柱上的"不同"

| Noita 支柱 | 我们的对应 | 差异化点（不是换皮） |
|---|---|---|
| 像素物理模拟 | **五行物质系统** | 物质除了物理属性，还带"五行"标签，与符的五行生克联动；加入糯米、黑狗血、朱砂、水银、香灰、纸钱等"民俗化学" |
| 法杖编辑 | **符箓三段式**（符头/符胆/符脚） | 道教符的真实结构天然就是"修饰符→主体→押印"，比 Noita 的修饰链更可读，且**符脚**引入"命中后载荷"这一层 |
| 永久死亡、无数值元进度 | **祠堂 + 怨灵** | 死去的角色进祠堂成牌位，下一局会在同层以"怨灵"形式出现，拿着你死时的法器——打赢它可以收回 |
| 隐藏秘密 | **河图洛书 / 卜甲 / 九鼎 / 鲁班书** | 秘密语言全部来自中国本土的数术体系：洛书幻方、六十四卦六位二进制、二十八宿 |
| （Noita 没有） | **三魂七魄双资源** | 身（七魄）与神（三魂）分开损耗；神智归零不是死亡，而是"入魔"——进入另一条玩法路线 |
| （Noita 没有） | **阴阳两界 + 纸扎** | 同一层地图有"阴面"镜像；把东西烧掉就能送到阴间——物理模拟里真的要烧干净 |

> **📝 批注 C04｜P1｜差异化审计｜原文 L28**  
> 本表混合了“改变核心循环的差异”和“题材包装/内容差异”。符脚触发载荷在 Noita 中并非全新概念；阴阳世界也不能只靠“地图镜像”证明差异。建议新增一列：玩家具体多了什么决策，且能否在前 10 分钟体验到。


### 1.2 核心循环（单局 30–90 分钟）

```
山门（道观/祠堂）出发
 └→ 逐层下潜：探索 → 拾取符/法器/银两/丹材 → 战斗（世界本身是最大的敌人）
     └→ 洞天（层间安全区）：传法(perk) / 鬼市 / 丹炉 / 纸扎铺 / 香案
         └→ 鬼门（可选）：进入本层阴面，走另一条路，付出神智
             └→ 归墟 → 混沌（结局分支）
死亡 → 祠堂记录死因与牌位 → 知识（而非数值）带入下一局
```

> **📝 批注 C05｜P1｜核心循环｜原文 L39**  
> 30–90 分钟跨度大，且主循环几乎是 Noita 的结构。建议给出 5 分钟、15 分钟、30 分钟三个阶段的体验目标，并定义一次局内“知识发现”的最低频率。第一个版本不承诺完整局长。


### 1.3 符箓系统（核心中的核心）

**法器 = 法杖容器**。属性：灵力上限、回灵速度、符位数、每念几符、施法间隔、回符时间、散布、有序/乱序（"成文"/"散符"）。法器种类带天赋：

> **📝 批注 C06｜P1｜法器属性｜原文 L43**  
> “每念几符”在后文用作句子数量，但符位表示槽位数量；应明确“符/句/轮/回符”的基本单位。法器可先保留灵力、间隔、符位三个控制项，其余在玩法验证后引入。


- 桃木剑（金系加成、近战挥砍可打飞刚体）
- 铜钱剑（第一个符脚免费）
- 拂尘（回灵极快、低伤、可扫开气体）
- **葫芦**（可装任何模拟液体，然后作为符胆喷出——玩家自己从世界里"采集"弹药，例如装一葫芦水银）

> **📝 批注 C07｜保留｜葫芦机制｜原文 L48**  
> 这是比单纯“换皮法杖”更有潜力的交互：从地图采集物质并反馈到施法系统。首个原型可限制为水、油两种液体，并明确容量、装填速度、喷射速率、残留及混液规则。

- 罗盘（自动瞄准）、铜镜（反射投射物）、铃（范围震荡）、幡（召唤）、笛（魅惑妖兽）、法印（定点领域）

**符 = 三段结构**（念符时从左到右"读"）：

| 段 | 作用 | 对应 Noita | 例子 |
|---|---|---|---|
| **符头**（敕令） | 修饰/触发 | modifier / trigger | 急急如律令（减施法间隔）、敕·触（碰撞触发下一句）、奉·时（定时触发）、天罡（加伤）、分身（多重） |
| **符胆**（主体） | 投射物/光束/领域/造物 | projectile | 飞剑(金)、毕方火(火)、五雷(雷)、鬼火(阴·只夺魄不伤身)、墨弹(留墨液)、藤生(木·造木质物质)、土遁(土·挖掘) |
| **符脚**（押印/煞） | 命中/结束后载荷 | （新增层） | 煞（爆）、化·水/化·金（命中物质转化）、镇（定身）、噬（吸血）、归（回灵）、散（分裂）、返（回旋） |

> **📝 批注 C08｜P0｜真正的新语法｜原文 L57**  
> 符头/符胆/符脚的文化结构很直观，但在机制上仍接近已有的修饰—投射物—触发载荷链。差异化应来自更严格或更自由的“施法语言”语义，例如条件、作用对象、持续状态、物质转换，而不是仅增加一个符脚槽。


规则：符头累积进"施法状态"；遇到符胆就生成投射物，并把其后**连续的**符脚附着上去；一句读完，按"每念几符"决定本次读几句。乱序法器随机抽句（对应 Noita 的 shuffle）。

> **📝 批注 C09｜P0｜形式语义缺失｜原文 L59**  
> 此段是整个项目最需要先冻结的协议：定义抽牌游标、连续符脚归属、多重符胆的共享状态、触发时序、乱序作用粒度、法力不足时行为，以及无效句处理。应先产出可执行测试用例和语法树/中间表示，再写 VM。


**五行生克作为第二层数值**：符胆的五行 vs 命中物质/敌人的五行——相克 ×1.5，被克 ×0.6，相生时投射物"喂养"目标（火打到木材→引燃范围扩大）。这让"打哪儿"和"用什么打"都有物理和数值双重意义。

> **📝 批注 C10｜P1｜五行关系｜原文 L61**  
> “火打木→引燃”是燃烧等物理反应，不是传统五行中“相生”的方向表达（传统是木生火）。建议将五行数值关系写为有向图，将物质燃烧/导电/溶解保留为独立反应规则，避免一套标签承担两种含义。


**禁符**：最强的符要求 **神智 < 某阈值** 才能念——"唯疯者可执之"。这是克苏鲁"知识即代价"的核心表达，也是入魔路线的入口。

> **📝 批注 C11｜P1｜禁符门槛｜原文 L63**  
> 低神智才能施法有鲜明风格，但会诱导玩家主动刷低神智，并可能与“神智下降影响操作可读性”发生冲突。建议禁符用“允许进入高风险施法态”而不是单纯阈值钥匙，并给出可预测的代价。


### 1.4 三魂七魄（身与神）

- **七魄 = 气血**。UI 是**七星灯**（诸葛亮续命那种）。普通伤害扣气血；**阴性伤害**（鬼、咒、煞气）会直接"熄灯"——每熄一盏，气血上限 -1/7，普通回复无法点回，只有糯米、黑狗血、香案、洞天续命能复燃。

> **📝 批注 C12｜P1｜气血与魄灯｜原文 L67**  
> 需要明确：七盏灯是七个离散上限段，还是可连续损耗的资源？后文“鬼火熄灯 0.3 盏/次”与这里的离散熄灯相冲突。建议使用单独的“魄损伤积累值”，达到阈值才熄灭一灯。

- **三魂 = 神智**（0–100，三个阈值）：
  - 失**爽灵**（<66）：UI 腐坏——符名变乱码、法器属性不可见、地图消失（"你读不懂了"）

> **📝 批注 C13｜P0｜玩家信息可读性｜原文 L69**  
> 游戏的核心乐趣是理解、调试复杂符组合。将符名乱码、法器属性隐藏会直接破坏这一乐趣；可保留视效腐坏、异常提示、幻觉对象，但不要随意剥夺对已经学会的规则的读取能力。

  - 失**胎光**（<33）：视野变暗，出现幻觉敌人（**有些是真的**）
  - 失**幽精**（=0）：**入魔**——周期性失控、身体变异、鲛人等族群停止攻击你，部分区域对你开放。这不是 Game Over，是另一条路线和结局。

> **📝 批注 C14｜P1｜入魔路线成本｜原文 L71**  
> “不是死亡而是另一玩法路线”意味着角色控制、AI 阵营、地图访问、UI 和结局内容均需额外制作。建议视作完整资料片级功能；第一版可仅做一个可逆/短时的入魔状态。

- 神智来源与去向：目睹不可名状之物（视野内持续掉）、读禁书（一次性大掉，换符）、呆在阴面、念禁符；回复靠香、茶、酒（酒回神智但手抖散布变大）、傩面（挡损耗但遮视野）、洞天静坐。

### 1.5 阴阳两界与纸扎（最有辨识度的新机制）

- 第 3 层起出现**鬼门**。穿过去进入**同一层的阴面**：布局同源（同一 seed 生成），物质映射替换（水→墨、火→阴火、土→香灰、金→纸钱、木→纸扎骨架），调色板变成纸与墨。
- 阴面是**另一条路**：阳面的死路在阴面可能是通的，反之亦然。
- **纸扎**：在纸扎铺用银两和纸做出任何物品的纸版（法器、符、丹、甚至一个纸人同伴）。**在模拟中把它彻底烧掉**——沾水就废、烧一半只送到一半——阴面就会出现对应的"阴器"。反向带出阴面的东西，天亮（游戏有昼夜）化为灰。

> **📝 批注 C15｜P0｜纸扎跨界语义｜原文 L78**  
> 这是极有辨识度的招牌机制，但“烧一半只送到一半”对武器、NPC 和组合物没有通用定义。需要物品唯一 ID、燃烧状态、交易式转移事件与重复领取防护；先对标准纸船/纸人各实现一个完整闭环。

- 两种货币：**银两**（阳）与**冥钱**（阴）。烧银 1:10 换冥钱，墓葬里能直接捡到冥钱（陪葬品）。

> **📝 批注 C16｜P1｜经济套利｜原文 L79**  
> 银→冥钱与夜间不同汇率的描述，需要说明能否逆向兑换、货币是否跨局、物品是否存在跨界价差。否则纸扎/转化符/当铺可能形成无限套利。


### 1.6 五行物质系统（模拟材料清单起点）

来自《天工开物》《本草纲目》《抱朴子》的材料，天然就是一张"化学反应表"：

- **液体**：水、桐油、酒、血、墨、水银（密度大于铁——铁会浮在水银上）、尸水、漆（粘且易燃）、蜂蜜
- **粉末**：沙、煤、硝石、硫磺、朱砂、石灰、香灰、糯米、盐、雄黄、纸钱
- **固体**：岩、玉、铁、金、陶/瓷、竹/木、雷击木、桃木、冰
- **气体**：阴气、瘴气、煞气、龙气、蒸汽、硫烟
- **特殊**：蛊（虫群粒子）、太岁（肉质、会再生的"物质"）

> **📝 批注 C17｜P1｜材质范围｜原文 L89**  
> 当前名单已包含连续流体、颗粒、固体、气体、生物群体、自愈材料等不同模拟范式，不能视作“填表就能增加内容”。建议先按行为模型归类：静态、颗粒、液体、燃烧、气体；太岁/虫群后置。


反应示例：硝+硫+炭+火→黑火药爆炸；石灰+水→放热蒸汽；糯米+尸气→净化；黑狗血+鬼→灼伤；水银+任何"旧日之物"→它们不能越过（后面世界观会解释为什么）；朱砂+墨+纸→现场画符。

> **📝 批注 C18｜P1｜反应层次｜原文 L91**  
> 这里混合了物理反应、化学幻想、民俗驱邪与剧情禁令。建议在数据结构中分“物质反应”“符法交互”“叙事规则”三层，不强迫所有反应都用相同的 A+B→C 格式表示。


### 1.7 秘密层（给核心玩家的几百小时）

- **卜甲**：捡到龟甲，用火烧，模拟系统里真实裂出的纹路就是地图提示（"卜"字本来就是裂纹）。
- **洛书幻方**：九口大缸，往里灌不同密度的液体，让每行每列每对角线"重量"相等——纯物理解谜。
- **六十四卦**：石碑上的卦象是 6 位二进制，整个世界的密码系统。
- **九鼎图**：大禹铸九鼎"图画百物，使民知神奸"——九鼎碎片就是跨局的图鉴/知识进度。
- **鲁班书**：可读的禁书，学了"必缺一门"：鳏寡孤独残——随机永久失去一盏魄灯/一个魂阶/一个符位/一只手的操作……但威力巨大。
- **太岁头上动土**：在太岁上方挖掘，它就醒了。字面意思变成机制。
- **凿混沌七窍**（终极秘密）：《庄子》里倏与忽给混沌凿七窍，"七日而死"。最终 Boss 帝江对一切伤害免疫，唯一解法是用挖掘类符在七个特定位置各凿一窍，每窍需要游戏内一日——顶级玩家的弑神路线。

> **📝 批注 C19｜P1｜秘密设计｜原文 L101**

### 2.2 历史：五纪（架空，但每一条都有原典可考）

1. **混沌纪**：帝江在笛声中起舞。盘古不是英雄，是"第一道伤口"。世界是盘古的尸体——岩是骨，水是血，龙脉是骨髓。**你一路向下挖的，是一具尸体。**
2. **补天纪**：共工撞不周山，天裂，"它们"从裂缝渗入。女娲以五色石（五行之物）补天——补丁在漏。天倾西北、地陷东南，万水归于**归墟**，裂缝就在那里。烛阴被放在钟山当"灯"看守。
3. **治水纪**：大禹锁相柳，铸九鼎、图百物以"使民知神奸"。《山海经》（旧传禹、伯益所作）即是最早的图鉴，也是最早的禁书——**知道它们的名字能护身，也会被它们听见**。
4. **求仙纪**：始皇遣徐福东渡，徐福抵达归墟，回来的已不是人。始皇陵以**水银为江河**——水银是"它们"无法越过的东西，陵墓是封印。历代帝王求丹吃汞，不是愚昧，是被"它们"引导着把封印吃掉。
5. **大晏末（游戏当下，晚明质感）**：矿监税使奉旨在**渎县**（"渎"：既是河渎，也是亵渎）采朱砂炼汞，挖穿地宫、龙脉，直通归墟。一夜之间全县消失。天师府每年派一名方士下山，无人归来——**祠堂里的牌位，就是你之前的所有角色**。

> **📝 批注 C23｜P1｜轮回叙事一致性｜原文 L134**  
> 祠堂里出现“之前所有角色”的设定，需要解释不同单局是否共处同一历史时间，以及每年派一名方士的时间推进。否则固定 NPC 与前次玩家怨灵的时间顺序会冲突；建议用“归墟时间不连续”或明确跨局年表解决。

> **📝 批注 C30｜P0｜无限经济漏洞｜原文 L218**  
> “命中物质→金”若可永久改变地图中的可售物质，会与金属价格、购买法器和重掷经济构成无限资源回路。可以允许强力炼金，但应约束转化范围、金的交易价值或施法材料成本，并明确“可利用漏洞”和“破坏进度”的界限。


**法器生成（按深度 L=1..7，预算分配法）**：

```
budget = 25 + 12*L + rand(-5, +5)
# 按随机权重把 budget 分到 6 个维度，允许"牺牲"（某维度为负换其他维度加成）
符位      = clamp(2 + w1*budget/8, 2, 24)
每念几符  = 1 + (rand < 0.1*L ? rand(1,3) : 0)
灵力上限  = 50 + 30*L + w2*budget*4
回灵/s    = 10 + 8*L + w3*budget*2
施法间隔  = clamp(0.50 - 0.05*L - w4*budget*0.01, 0.02, 0.5)
回符时间  = clamp(0.80 - 0.07*L - w5*budget*0.01, 0.05, 0.8)
散布      = clamp(10 - w6*budget*0.3, -5, 20)   # 负散布=聚拢
乱序概率  = L < 3 ? 0.5 : 0.3
```

> **📝 批注 C31｜P0｜生成器规格｜原文 L233**  
> 此公式列出八项法器属性，仅六个分配权重；w1…w6 如何抽样、是否允许负数、如何归一化与保证预算守恒均未定义。建议先定义“可解释的品质预算”和约束求解，使用 Monte Carlo 检查极端生成结果。


### 3.4 伤害公式

```
伤害 = 基础 × 法器倍率 × Π(符头加成) × 五行系数 × (1 - 抗性)
五行系数：相克 1.5 / 被克 0.6 / 相生 1.0 但触发"喂养"效果 / 其他 1.0
伤害类型：金(切/刺) 木(毒) 水(冰/溺) 火(灼) 土(钝/压) 雷(电/天谴) 阴(夺魄) 阳(净化·对鬼 ×2) 蛊(DoT) 汞(中毒累积)
```

> **📝 批注 C32｜P1｜伤害分类｜原文 L241**  
> 五行是关系标签，“雷/阴/阳/蛊/汞”是伤害机制，混放在一个类型集合里会使抗性表膨胀。建议拆分元素标签、伤害通道、状态效果三列；同一次攻击可同时具备多维标签。

> **📝 批注 C33｜P0｜敌人与玩家成长失配｜原文 L253**  
> “每层 HP≈×1.8，符 Tier≈×1.6”不自动保证小怪 2–5 发被击败。玩家叠加修饰符、攻击频率、命中率、暴击、范围清怪能力等均未给出。建议通过真实构筑分位数（弱/中/强）模拟击杀时间，而非只比较单符伤害。


### 3.6 经济流

- **收入**：每层约 `300 × 1.5^(L-1)` 银（L1 300 → L6 2278）。
- **符价**：`80 × 2^(t-1) × (1±0.3)`（T1 80 … T5 1280）。
- **法器价**：`250 × 1.6^(L-1)`。
- **传法重掷**：冥钱 `100 × 2^n`。
- **当铺**（Noita 没有的回收渠道）：4 折收、7 折赎（限本层），用当票做风险决策。
- **纸扎**：物品价值 50% + 纸；烧毁失败即损失。
- **赌坊**（鬼市）：牌九/骰子，用冥钱，期望值为负但方差大——给绝境玩家翻盘。
- **货币汇率本身是机制**：烧银换冥钱的 1:10 固定，但在"子时"烧是 1:5——昼夜系统与经济挂钩。

> **📝 批注 C34｜P1｜汇率方向｜原文 L264**  
> 文中普通烧银 1:10，子时 1:5；若子时本应强化阴间交易，这个数值反而让银能换到更少冥钱。请明确这是刻意的“子时税”还是方向写反，并测试多系统套利。


### 3.7 平衡方法论

1. 所有数值放在数据表（TOML/CSV），热重载。
2. 建一个 **headless 跑局机器人**：用脚本代理跑几千局，输出各层死亡分布、伤害来源 Top10、经济曲线。目标曲线：新手 40% 死在前两层、单局中位 25 分钟；熟练者首通 30–60 小时。
3. EA 期间收集遥测（死因、符组合使用率），用"死因排行榜"驱动调整——Noita 的平衡本质是靠玩家发现。

> **📝 批注 C35｜P1｜机器人与玩家指标｜原文 L270**  
> Headless 大批量跑局可以发现经济漏洞、系统死锁和数学分布，但脚本代理不能替代人类玩家测试“有趣”“可理解”“公平”。新手 40% 死于前两层、首通 30–60 小时都是待检验目标，不应成为初版硬约束。

## 四、引擎选型与代码架构

### 4.1 技术核心需求（决定一切的前提）

Noita 的落沙模拟很简单，液体和气体用同样思路；刚体用 marching squares；世界切成 64×64 的 chunk，每个 chunk 维护一个脏矩形只模拟需要动的像素，并靠多线程扩展 [cite:313b1036-1]。这意味着：**无论选什么引擎，像素模拟核心都要用原生语言自己写**，引擎只负责"周边"（渲染上传、UI、音频、本地化、平台）。

> **📝 批注 C36｜P1｜技术结论过强｜原文 L278**  
> “无论选什么引擎，都要用原生语言自己写”是可能合理的长期方案，但不应成为先验结论。可先用极简 C++/Godot 原型做性能对照；Noita 的公开实现经验也不能等价于本项目性能证明。


### 4.2 选型对比（2026 年视角）

| 方案 | 优点 | 缺点 | 适合谁 |
|---|---|---|---|
| **A. 自研**（C++/Rust + SDL3/wgpu + Box2D v3 + Lua） | 极致控制，Noita 路线；零授权费 | 编辑器、工具、移植、输入、音频全得自己做；至少 1 名资深引擎程序 | 核心成员本身是引擎程序员 |
| **B. Godot 4.6 + GDExtension**（C++ 或 Rust 写模拟核心） | 免费开源、可改引擎源码；GDExtension 接口已改为 JSON 定义便于绑定；支持 Tracy/Perfetto 等追踪式 profiler；Windows 默认 D3D12；2025 年 Steam 新增超 1200 款 Godot 游戏 [cite:313b1036-2] | Godot 自带 2D 物理不适合像素刚体，需自带 Box2D；主机移植靠第三方；2D 世界纹理上传需自定义 | **中小团队、主打 PC、重视开源可控（我的默认推荐）** |
| **C. Unity 6 + C# Jobs/Burst** | 国内人才池最大；主机发行成熟；内置 2D 物理 | Personal 仅限年收入与融资 ≤ 20 万美元，超过需 Pro，2026 年 Pro 为每席 2310 美元/年；Runtime Fee 已取消 [cite:2246f3cb-1]；像素模拟在 C# 里需要 unsafe/NativeArray 纪律 | 已有 Unity 班底、需要快速多平台 |
| **D. Bevy 0.20**（Rust） | ECS 原生、Rust 并发安全；0.20 已支持自定义 Sprite 材质与 2D 扩展材质，采用 WESL 着色语言 [cite:313b1036-3] | 编辑器仍在建设中、版本间 API 变动大（BSN 场景语法刚稳定）、人才少 | Rust 团队，能接受 churn |

> **📝 批注 C37｜P2｜技术选型时效｜原文 L287**  
> 引擎版本、授权条款、具体渲染器默认值、Steam 游戏数量和 Bevy API 均是时间敏感信息。原文 [cite:...] 未提供可直接核验的链接；正式立项前由工程负责人逐条核查并写入决策记录，避免让模型按未经验证的版本假设生成代码。


**物理库**：无论哪条路都建议 **Box2D v3**——纯 C、全新 API、速culative 连续碰撞、SIMD + 多线程求解；作者明确提到其多线程设计受到 Noita 技术分享的启发，专门支持"大堆刚体" [cite:313b1036-4]。这正是像素刚体碎块的场景。

**我的推荐**：把模拟写成**引擎无关的独立库**（`sim_core`，C ABI），再宿主到 Godot（默认）或 Unity（如果班底是 Unity）。这样引擎选错了也不用重写核心。

> **📝 批注 C38｜P1｜过早抽象｜原文 L291**  
> 独立 sim_core + C ABI 是可维护的方向，但也引入跨语言调试、纹理与内存所有权、Godot 绑定的复杂度。第一阶段可以先保留“独立纯逻辑模块”原则，不必同时承诺跨 Godot/Unity 兼容。

> **📝 批注 C39｜P1｜架构边界｜原文 L311**  
> 应区分“引擎侧节点/资源系统”与额外 ECS；两套实体生命周期如果并存，需要明确谁是权威状态。第一版不必同时提供 Lua/GDScript Mod 钩子、编辑器、回放和独立平衡代理。


### 4.4 模拟核心细节

**Cell 布局**（4–8 字节）：
```c
struct Cell { uint16_t material; uint8_t flags; uint8_t life_or_temp; uint32_t color; };
// flags: updated_this_tick | burning | rigid_owned | wuxing(3bit)
```

> **📝 批注 C40｜P1｜Cell 数据布局｜原文 L319**  
> 结构体实际通常为 8 字节，但 flags 中的“wuxing(3bit)”可能与 material 表重复；life_or_temp 合并意味着有些状态不能同时表示。建议显式区分 per-cell 热数据与 per-material 静态属性，并用缓存/带宽测试选择布局。


**Chunk 与多线程**：64×64 chunk + 脏矩形；每 tick 分 4 个 pass，按棋盘格（cx%2, cy%2）分组，同一 pass 内任意两个 chunk 至少隔一个 chunk，线程可以安全读写相邻格子不加锁。chunk 静止后脏矩形为空，成本为零。

> **📝 批注 C41｜P0｜并发正确性｜原文 L321**  
> 四组棋盘格只能减少 chunk 邻域冲突，不能自动证明边界写入、邻区脏标记和跨块粒子迁移是无数据竞争的。应规定单写者、边界事件缓冲、pass 屏障及确定性执行顺序，并设计 ThreadSanitizer 与回放一致性测试。


**更新规则**：
- 粉末：下 → 左下/右下；液体：下 → 水平扩散（dispersion 参数）；气体：上；固体不动；`rigid_owned` 格子归 Box2D 管。
- 反应表（数据驱动）：`(A, B) -> (C, D, prob)`，例如 `(火, 桐油) -> (火, 火, 0.8)`、`(水, 岩浆) -> (蒸汽, 岩, 1.0)`、`(糯米, 尸气) -> (糯米, 空, 0.5)`。
- 火 = 带寿命的格子状态，按 `flammability` 向邻格传播；电 = 每 tick 从电源对导电格子做有上限的 BFS。
- 温度可选：先不做，用"火作为物质"覆盖 80% 需求。

> **📝 批注 C42｜P1｜材质更新架构｜原文 L327**  
> “火作为物质”可能导致燃烧中的木材无法同时保留其原材质性质；“覆盖 80% 需求”缺少依据。可使用燃烧标志/燃料计数；温度系统先不实现，但数据结构需允许未来扩展。


**像素刚体**：被炸裂的物体像素 → flood fill 分岛 → marching squares 轮廓 → Ramer–Douglas–Peucker 简化 → 耳切三角化/凸分解 → Box2D 形状。每帧把刚体的像素按新变换写回世界（标记 `rigid_owned`）；像素被破坏则重新提取；休眠或静止后转回静态像素。

> **📝 批注 C43｜P0｜刚体提取与同步｜原文 L329**  
> 动态 flood fill、轮廓提取、凸分解、形状替换、像素反写是独立研发课题。Box2D 只处理刚体，不代替地形拓扑与栅格同步。先限制为静态地形破坏+少量预制刚体，破碎刚体作为单独实验，不要放进首个可玩原型的必备路径。


**确定性**：固定 60Hz；RNG 用 PCG，按 `(tick, chunk_id)` 派生种子，保证多线程下可复现（支持每日挑战、seed 分享、bug 回放）。

> **📝 批注 C44｜P0｜确定性假设｜原文 L331**  
> 固定 60Hz 与按 tick/chunk 设 PCG 种子仍不足以保证多线程可复现：事件合并顺序、邻块更新顺序、浮点实现和刚体求解都影响结果。应单独定义“可复现级别”：同机器/同版本、跨机器、网络一致性，并测试相同 seed 的状态哈希。


**性能预算**：活动窗口约 3×3 屏（~3.7M 格），只有脏矩形参与计算，目标 4 线程 ≤ 4ms。

> **📝 批注 C45｜P0｜性能预算｜原文 L333**  
> 约 370 万格、四线程 4ms 是未经压测的目标，不是技术可行性结论。若每格 8 字节，单层栅格数据约 29.6MB，不含额外缓冲与上传开销；需要分别测更新、构图、纹理传输与 GPU 后处理的时间，并选定目标硬件。


### 4.5 符箓 VM（伪代码）

```rust
fn cast(wand: &mut Wand, deck: &[Spell]) -> Vec<CastAction> {
    let mut actions = vec![];
    let mut state = CastState::default();        // 累积符头修饰
    let mut sentences = wand.spells_per_cast;    // 每念几符
    while sentences > 0 && let Some(s) = wand.draw(deck) {   // 乱序法器随机抽
        match s.kind {
            Head(modifier) => state.apply(modifier),
            Head(Trigger::OnHit) => state.trigger = Some(cast_sub(wand, deck)), // 触发：递归读下一句
            Body(projectile) => {
                let mut p = projectile.instantiate(&state);
                while let Some(Foot(payload)) = wand.peek() { p.payloads.push(wand.draw_foot()); }
                actions.push(CastAction::Spawn(p));
                state = CastState::default();
                sentences -= 1;
            }
            Foot(_) => { /* 没有符胆的符脚：无效，消耗灵力（鼓励玩家读懂结构） */ }
        }
        wand.mana -= s.cost;
    }
    actions
}
```
Deck/hand/discard 的模型可以直接借 Noita 的思路，符脚是额外的 `peek` 循环。

> **📝 批注 C46｜P0｜VM 执行风险｜原文 L360**  
> 递归 cast_sub 在触发符下可能产生循环、爆炸式生成与不可预测的法力消耗。建议编译为带预算的事件/字节码：限制递归深度、单次动作数、投射物数、延迟触发生命周期，并定义失败时的原子性与资源扣除时点。


### 4.6 世界生成与存档

- 每层 = 手绘材质图（PNG 颜色→材质）+ Wang 瓦片集 + 噪声叠加 + "场景预制"（庙、棺、桥、矿车）+ 刷怪图；洞天用固定模板。
- **阴面** = 同一 seed、同一布局、一张"材质映射表"和"实体替换表"——实现成本低，体验收益高。
- 存档：只存相对生成基线的 chunk 差分（RLE + zstd）+ 实体 + seed；死亡时把死点、法器序列化进祠堂，供下一局生成怨灵。

> **📝 批注 C47｜P1｜状态持久化｜原文 L366**  
> “同 seed + 物质映射”不等于低成本双世界，任意挖掘、燃烧、携带物品、纸扎转移都会改变拓扑和事件因果。应决定双世界是独立状态、共享基线还是单向派生；差分存档也必须考虑事件、跨界实体 ID 和版本迁移。


### 4.7 渲染：水墨不是贴图，是后处理

chunk 纹理 → Sobel 边缘提取成墨线 → 宣纸颗粒叠加 → 液体区域做"湿边晕染"（按液体 mask 模糊）→ 每层有限调色板；阴面切换为去饱和 + 纯墨。光照用降采样遮挡图在 shader 里做 2D 光线步进。UI 用宣纸、朱印、竖排。这一套让它在第一眼就和 Noita 区分开，成本却很低。

> **📝 批注 C48｜P1｜水墨美术成本｜原文 L370**  
> Sobel 描边、宣纸噪声、湿边晕染不能保证自动形成有辨识度的水墨美术；还需材质层级、角色剪影、信息高亮和可读性测试。建议制作静态/动态场景美术原型，测量渲染成本，再确定完整后处理方案。


### 4.8 数据驱动与 Mod

材质、符、法器、敌人、掉落、丹方全是数据文件；Lua（自研/Unity）或 GDScript（Godot）暴露生命周期钩子。Noita 的长寿很大程度上来自 Mod 社区，这点从第一天就要预留。

> **📝 批注 C49｜P2｜Mod 时间点｜原文 L374**  
> “从第一天预留可数据覆盖的规则”合理，但第一天引入脚本钩子、沙盒权限、兼容版本与 Mod API 容易分散精力。先做到数据驱动和模块隔离，公开 API 在玩法稳定后建设。


### 4.9 里程碑与团队（4–6 人）

| 阶段 | 时间 | 目标 |
|---|---|---|
| M0 | 6–8 周 | `sim_core` + 角色 + 1 个符 + 刚体碎裂。**只验证手感**，手感不对就停 |
| M1 | 3 个月 | 符箓三段式、3 种法器、矿井层、洞天、七星灯 |
| M2 | 6–9 个月 | 垂直切片：2 层 + 阴面 + 鬼市 + 祠堂怨灵 + 水墨后处理 → Steam 新品节 Demo |
| M3 | 12–18 个月 | EA（4 层 + 入魔路线） |

团队：1 引擎/模拟程序（C++/Rust）、1 玩法程序、1–2 像素美术（其中一人管水墨与 UI）、1 策划/数值、音频外包、文案兼职。

> **📝 批注 C50｜P0｜里程碑与团队｜原文 L385**  
> 4–6 人、12–18 个月的计划不应直接平移为“1 人 + 多个 AI Agent”。AI 生成代码不等于完成调试、可玩性验证、视觉资产、音频和发行。建议把 M0 重写为 2–3 个独立 go/no-go 实验：物理性能、符语义、10 分钟手感；后续日期采用测量后的区间。

## 五、三个必须提前想清楚的风险

1. **版号与题材**：鬼、血、迷信、邪教在国内审核中都是敏感点。建议从立项起就做"词表可替换"（鬼→灵/妖，血→墨）、血液用墨色可选项，并以 **Steam 全球优先**规划收入，国内版号作为上行选项而非前提。

> **📝 批注 C51｜P1｜发行合规｜原文 L391**  
> 面向不同地区发行时应分别研究当地内容合规、平台政策、评级、个人信息与收款税务问题。“鬼→灵/妖”词表替换不足以解决完整内容审核；此段是风险提示而非确定的法律结论。

2. **"这不就是 Noita 换皮"**：前 10 分钟必须让人看见符箓三段式 UI、七星灯、水墨画面三样东西中的至少两样。差异化不能藏在第 4 层。
