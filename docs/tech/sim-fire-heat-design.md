# 火焰/热系统设计参考：Noita vs 我的世界，我们怎么借鉴

> 状态：**设计参考（2026-11-17）｜结论：留到 M1 做，M0 不扩 scope**
> 触发：用户问「火焰 Noita 和我的世界怎么处理？如何借鉴？还是留到下一阶段？」
> 相关：D1（可读元素沙盒：sim_core + 反应表 + 符箓 VM 是唯三深做系统）、D4（M0 只做 5 物质 + 挖掘）、C-SIM v2、C-DATA、C-EVT/C-TEXT（M1 契约）。

## 0. 结论先行

| 问题 | 答案 |
|---|---|
| Noita 怎么做 | **火就是一种材料**，不是独立系统：材质有不同燃烧速度、燃烧产物、烟/蒸汽；生物有「点燃」状态（2% 最大生命/秒 + 移速 +15% + 恐慌）；水/黏液灭火、油/威士忌助燃、潮湿保护；「热源 + 可燃材料」作为反应传播 |
| 我的世界怎么做 | **方块火 + 老化**：火方块 age 0–15、每 1.5–2 秒调度一拍；3×3 水平、上方 4 格/下方 1 格内传播；点燃概率 = 基础值 + age + 难度 + 相邻可燃性；无相邻可燃物就熄灭；水/雨灭火；生物带 Fire 计时（160 ticks）持续燃烧掉血；**只更新玩家 8 区块内的火**（性能） |
| 我们怎么借鉴 | **取 Noita 的「材料化 + 反应表驱动」，取我的世界的「老化/熄灭条件 + 邻近更新预算 + 可预测规则」**；不照搬代码/数值/固定 3×3 网格/难度公式 |
| 现在做还是留到下一阶段 | **留到 M1**（MVP 的反应表阶段）。M0 只验证性能/语义/手感；T4b 的火已经是够用的灰盒占位。M0 期间只允许调灰盒数值，不新增系统 |
| 为什么不是现在 | 火系统必须与**反应表执行器**一起做才有意义（我们的 `data/materials.json` 已有 8 条反应/3 条 heat 触发，但引擎还没有反应表）；且会改 C-SIM 语义/性能预算，而目标机还没测（D4 要先量性能）；M0 scope 已冻结 |

## 1. 现状（T4b 灰盒，事实核对）

| 项 | 现状 | 差距 |
|---|---|---|
| 火 | C-SIM 里 fire 是带寿命的气体（40–110 tick），邻格可燃材质按概率点燃（当前仅油 5%/tick），水接触熄灭 | 没有温度/点燃阈值；没有烟；没有燃烧产物；没有实体燃烧 |
| 数据 | `data/materials.json` 已有 `temperature`（水 20/水银 20/阴气 10）、`flammable`、`ignition_temperature`（煤 300/硫 250/竹木 200）和 heat 触发反应（黑火药 120、硫烟 80、竹木 200） | **引擎不读 `temperature` / `ignition_temperature`**；`flammable` 只设了标志，煤/硫/竹木的点燃概率仍是 0 → 灰盒里它们不会自燃，「瓦斯囊」目前只是色块 |
| 实体 | T4b 只有「站火边掉 7 盏」的灰盒 | 没有 burning 状态、没有湿身、没有烟窒息 |
| 反应 | 未实现反应表执行器 | 8 条反应的数据在 `data/`，等待 M1 执行器 |

## 2. Noita：材料化的火（事实 + 可借点）

| 事实 | 出处 | 可借 |
|---|---|---|
| 火是一种材料（3 种颜色变体，都标「火」）；爆炸/法术/灯笼/炸药桶产生火 | [Noita 中文 wiki·火焰](https://wiki.biligame.com/noita/%E7%81%AB%E7%84%B0) | 火进同一套 CA/材质表，不进独立系统；「热源 + 可燃材料」的接触反应传播 |
| 火焰点燃接触到的生物/可燃物；燃烧状态每秒 2% 最大生命、移速 +15%、敌人恐慌 | 同上 | 点燃做成实体状态（DPS 用百分比而非固定值），并给可读行为（恐慌/乱跑）；M1-02 战斗直接复用 |
| 水和很多液体灭火；油/威士忌让生物更易燃；潮湿状态能防止被点燃（湿了会快速消耗） | 同上 | **wetting/潮湿**是一个便宜又直观的防护状态；比「火抗」更符合民俗物质感 |
| 不同材料燃烧速度不同（威士忌/可燃气体几乎瞬间、煤最慢、油居中）；燃烧产生烟，烟会窒息 | 同上 | 每种材质配 `burn_time/burn_rate`、`burn_product`；烟是气体材质 + 窒息/毒伤事件 |
| 水碰火产生蒸汽，部分蒸汽会重新凝成水 | 同上 | 水+火 → steam 材质（可凝回水）；和 `r-lime-steam` 的 heat_cloud 共用表现 |
| 火可被特定法术冻结成粉状火焰颗粒，之后可能复燃 | 同上 | M2+ 的彩蛋/深层内容候选，不进 M1 |

**Noita 的关键教训**：火不是「系统」，是材质属性 × 反应表的涌现；所以玩家能读懂、能组合；代价是每种材质都要配燃烧数据、以及烟/蒸汽这类二级材质。

## 3. 我的世界：方块化的火（事实 + 可借点）

| 事实 | 出处 | 可借 |
|---|---|---|
| 火方块有 age 0–15；每 1.5–2 秒一次调度 tick（Java 版） | [Minecraft Wiki·Fire](https://minecraft.wiki/w/Fire) | **老化 + 明确计时**：火会自己走向熄灭，不会永远停留 |
| 传播范围：3×3 水平、上方 4 格/下方 1 格；点燃概率 = 基础值 + 难度 + age + 相邻最大可燃性；无相邻可燃物时火会熄灭 | 同上 | **传播半径/概率 = 数据 + 距离 + 年龄**；火必须有燃料，不能凭空蔓延 |
| 每种方块有 ignite odds / burn odds（点燃难度/烧毁速度），雨/水/细雪/炼药锅灭火 | 同上 | 材质表里放「点燃阈值 + 燃烧速度」；玩家有明确的灭火手段（我们的葫芦水就是） |
| 生物有 Fire 计时（160 ticks = 8 秒）持续掉血；火方块内伤害 1HP/半秒（有受伤无敌帧）；离开火源后继续烧 | 同上 | **实体燃烧计时器**与「火方块」分离：离开火源 still burning（可读、可预判） |
| 只有玩家 8 区块内的火才更新（性能门槛） | 同上 | **按玩家/活跃区域限制火更新**：和我们的 chunk 活跃区天然契合 |

**我的世界的教训**：规则要能让玩家「学会」——老化、燃料、灭火条件都可见可推理；同时用「只更新玩家附近」把模拟成本压住。

## 4. 我们的设计（M1 提案：C-SIM v3「热/火」+ 反应表）

> 原则：**不引入全局温度场**（逐格温度是性能陷阱，也不是我们需要的）；用「热源格 + 邻域阈值 + 反应表」表达；数据继续由 `data/materials.json` 驱动。

### 4.1 数据层（C-DATA 扩展，已有字段先用起来）

| 字段 | 用途 |
|---|---|
| `temperature`（已有：水 20/水银 20/阴气 10） | 环境基准温度；用于「热源 vs 环境」的局部判断与 UI 提示 |
| `flammable` / `ignition_temperature`（已有：煤 300/硫 250/竹木 200） | 点燃阈值：当相邻热源温度 ≥ 阈值时按概率点燃 |
| 新增 `burn_time`（或 `burn_rate`） | 燃烧持续/燃尽速度（Noita：威士忌快、煤慢、油居中） |
| 新增 `burn_product`（可选） | 燃尽产物（竹木→煤/香灰；硫→毒烟；油→火+烟） |
| `reactions`（已有 8 条，含 heat 触发 min_temperature） | 反应表执行器：同一格/邻格满足输入 + 温度条件时按 priority 执行第一条；`consumes` 决定保留/消耗 |

### 4.2 模拟层（C-SIM v3）

1. **热源**：火格带一个 `heat` 值（如 400；`temperature` 字段派生）；爆炸/heat_cloud 产生瞬时热事件；岩浆/灯笼等后续再扩。
2. **点燃**：每 tick 对活跃区内的热源邻域（3×3，Noita 式局部）检查可燃材质：`heat ≥ ignition_temperature` 时按 `P = base_rate × (heat−threshold)/scale` 掷骰点燃；火有 40–110 tick 寿命（沿用）；燃料材质被点燃后按 `burn_time` 转为火/产物。
3. **熄灭/蒸汽**：水邻接火 → 火变空 + 水有机会变 steam（新增气体材质，带寿命；可部分凝回水）；`spray water` 的灰盒规则升级为真实反应。
4. **烟**：新增 smoke/toxic_smoke 气体材质（`r-sulfur-toxic-smoke`、竹木燃烧副产）；烟格对生物施加窒息/毒 DPS（C-EVT 事件）。
5. **实体状态**：`burning_ticks`（照我的世界 Fire 计时）+ `wet_ticks`（Noita 潮湿保护）；燃烧 DPS 用最大生命百分比（Noita 2%/s，数值进 `magic_numbers.json`）；燃烧敌人恐慌/乱跑（复用 M1-06 AI）。
6. **性能**：只在活跃 chunk + 视野附近更新火/反应（照我的世界 8 区块门槛，我们按 active rect + margin）；每 tick 邻域检查；预算目标 < 0.5 ms（在 D4 的 6 ms 内）；目标机复测时专项加「全屏燃烧」场景。
7. **可读性（D1/C-EVT/C-TEXT）**：火/烟颜色 + 音效 + 事件文本至少两种通道；用 C-EVT 输出 `fire_ignited/fire_extinguished/smoke_created/burning_started/steam` 等事件给表现层。

### 4.3 分批

| 阶段 | 做什么 | 不做什么 |
|---|---|---|
| **M0（现在）** | 只保留 T4b 灰盒火（挡路/灭火/掉盏）；**不扩 scope**；用户试玩后只调灰盒数值（寿命/伤害/半径） | 不做温度/反应表/烟/实体燃烧 |
| **M1** | C-SIM v3：热/火/烟/蒸汽材质 + 反应表执行器 + 实体 burning/wet 状态 + C-EVT 事件；加「全屏燃烧」性能用例 | 不做冻结火焰、火法术流派、天气/雨 |
| **M2+** | 冻结火焰（Noita 彩蛋）、液体燃料（油/酒/血）、风/烟流动、火星/余烬粒子 | — |

### 4.4 明确不借鉴

- 不照搬 Noita 的代码/数值/材质规模（我们只做 12 物质起步，D1 的「可读」优先）。
- 不照搬我的世界的固定 3×3×3 网格、难度系数公式、无限燃烧方块（netherrack 类比）——我们的规则要服务「民俗物质 + 符箓」。
- 不做全局逐格温度场（性能/复杂度不划算；需要时用「热源 + 阈值 + 邻域」表达）。

## 5. 对当前 T4b 的影响（诚实说明）

- T4b 的「火障」剧情成立（火挡路 + 葫芦水灭火），但它用的是灰盒规则，不是真实反应表；玩家现在会看到：**油会烧、煤/硫/竹木只是可燃标志但不自燃**（引擎不读 `ignition_temperature`）。
- 所以「瓦斯囊」房间目前的硫磺/煤大块区域不会真的爆炸/冒毒烟——这是 M1 反应表的工作，不是 T4b bug。
- 如果用户试玩时觉得这块「假」，建议先只做两个灰盒补丁（不新增系统）：①火对可燃材质的点燃概率读取 `flammable`（已有标志）并给个统一 1–2%/tick；②executor 的 `ignite` 已能直接 set fire，可手动点火演示。是否做等用户反馈。
